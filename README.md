>
> 当前固件版本：**01.26.47.12**（含诊断接口 v3）
>
> 总线哨兵（立创开源工程）：https://oshwhub.com/sg-diy/project_tactlhci

## 一、这是什么

BMCU 完整介绍见社区 wiki（「什么是 bmcu」）：<https://bmcu.wanzii.cn/>

本仓库是基于上游 **V11** 的整合改版，包含源码与预编译固件。

| 内容 | 说明 |
|---|---|
| **固件源码** | 基于上游 [BMCU-C-PJARCZAK](https://github.com/jarczakpawel/BMCU-C-PJARCZAK) V11（作者 Paweł Jarczak）；BMCU 项目由 **4061N** 发起（[karlingen/BMCU](https://github.com/karlingen/BMCU)）|
| **预编译固件** | `firmwares/`，60 个变体（3 档位 × 5 槽位 × 4 退料长度），版本统一为 `01.26.47.12`，**全部含诊断接口 v3**；不想翻目录可直接下[发行版压缩包](https://github.com/ljl-sg/BMCU-C-SG/releases/latest)（60 个固件 + 选型表）|

### 相对上游的主要改动

本仓库在上游基础上**做了以下五项改动**，其余功能均沿用上游：

| 改动 | 说明 |
|---|---|
| **序列号承载配置信息** | 15 位：前 3 位 `B0C` 标识 BMCU 开源固件，后 5 位直接读出「槽位 / 自动进料 / 档位 / 退料长度 / 耗材灯」——有人问「这序列号什么意思」，只需报**最后 5 位** |
| **静默指令 0x04A0** | 接收 **BMCU-BusSentry-SG 总线哨兵** 下发的私有静默指令，静默指定毫秒后**自动重启**并重新注册，用于刷新打印机对 BMCU 的宽限期（约 132 秒）|
| **诊断接口 0x04A1 / 0x04A2** | 只读诊断：**总线哨兵**点「读取诊断」时一问一答，回报四通道的**压力 / 缓冲电压 / 触发电压 / 触发状态 / 角度 / 磁铁 / 编码器 / 装料 / 卡料**，以及运行时长、重启原因、注册与静默次数、总线错误、循环周期。**不做周期广播**，静默/重启窗口内不回包 |
| **版本号定义方式** | 改为构建追踪号 `01.<年>.<ISO周>.<当周序号>`，每次编译都能在打印机上看出版本 |
| **源码结构整理** | 按职责分包（`app/ bus/ motion/ storage/ drivers/ log/ config/ hal/`），拆出独立模块、统一命名、补头注释，并新增 [`docs/CODE-MAP.md`](docs/CODE-MAP.md)。**纯结构整理，不改行为。** |

> **说明**：序列号里的槽位字符只用于**区分刷写的是哪一个变体固件**；实际槽位由总线地址（固定槽位）或 `AMS_AUTO` 上电协商决定，不参与寻址。

另附：`build_all_firmwares.py` 是一键批量构建脚本（按三档位 × 五槽位 × 四退料长度编出 60 个常用变体）。

### 快速开始

1. **选固件**：按你的槽位（A/B/C/D/AUTO）、档位（soft / standard / high_force）、退料长度挑一个 `.bin`。最省事是直接下[发行版压缩包](https://github.com/ljl-sg/BMCU-C-SG/releases/latest)，解压后按 `which_to_choose.txt` 对号入座
2. **烧录**：打印机完全断电 → 拔下 BMCU → USB 接下载口 → WCHISPTool 选 **CH32V203C8T6**、地址 `0x00000000` → 下载
3. **装机**：BMCU 插回 AMS 口、打印机通电，等它注册（打印机的 AMS 页面能看到序列号就算成功）

不接 **总线哨兵** 也能正常打印，只是认证宽限期（约 132 秒）过后要手动断电重启一次；接上哨兵后这一步会自动完成。

> 可配合 **BMCU-BusSentry-SG 总线哨兵**（见「八、配套」）自动刷新宽限期，不用反复重启打印机。

## 四、固件选择（firmwares/）

```
firmwares/
├── high_force_load/   ← 高推力档（P 系列 / 长走线 / 阻力大）
├── standard/          ← 标准档（大多数情况）
├── soft_load/         ← 轻柔档（细线材 / 易卡料）
├── manifest.txt       ← 路径 / 大小 / SHA256 / CRC32
├── README.md
└── which_to_choose.txt
```

每个档位下按槽位分目录（`AMS_A` ~ `AMS_D`，以及 `AMS_AUTO`），目录内是该槽位的全部**退料长度**版本：

```
high_force_load/AMS_A/ams_a_0.20f.bin
                       ams_a_0.50f.bin
                       ams_a_0.70f.bin
                       ams_a_0.90f.bin

high_force_load/AMS_AUTO/ams_auto_0.20f.bin
                          ams_auto_0.50f.bin
                          ams_auto_0.70f.bin
                          ams_auto_0.90f.bin
```

**槽位怎么选**：

| 槽位 | 什么时候用 |
|---|---|
| `AMS_AUTO` | 默认选这个。上电后跟打印机协商槽位 |
| `AMS_A ~ AMS_D` | 打印机只认固定槽位时（老固件、或自动注册不生效）才用 |

> [!IMPORTANT]
> **单台或多台 BMCU 都建议按顺序刷写**
>
> - **只有一台**：刷 `AMS_AUTO` 即可，上电后自动协商槽位。
> - **同一条总线上挂多台**：逐台刷写、逐台确认注册成功后再刷下一台；
>   固定槽位时按 `AMS_A` → `AMS_B` → `AMS_C` → `AMS_D` 的顺序，
>   或全部用 `AMS_AUTO` 但**一台一台上电**让打印机逐个分配。
> - 一次全部接上电再刷，容易出现「多台抢同一槽位」或「刷错板子」，
>   排查时也分不清是哪一台出的问题。
>
> 刷完可用打印机「设备 → 固件更新」页或哨兵的 `/info`（`amsSer` 字段）
> 确认每台的序列号是否符合预期：`B0C<UID7><槽位><自动进料><档位><退料><耗材灯>`（配置看最后 5 位）。

**编译开关（发布变体默认值）：**

| 功能 | 宏 | 默认 |
|---|---|---|
| 自动进料（双微动，首次进料辅助） | `BMCU_DM_TWO_MICROSWITCH` | **开** |
| 在线灯显示耗材颜色 | `BMCU_ONLINE_LED_FILAMENT_RGB` | **关** |

想开耗材颜色显示，在对应的 env 里补一行 `-DBMCU_ONLINE_LED_FILAMENT_RGB=1` 再编。

详细挑选方法见 `firmwares/which_to_choose.txt`。

## 五、固件版本号与序列号命名规则

上游 `version` 里是发布版本号（V11 = `11.00.00.00`，V10.5 = `10.50.00.00`）。本仓库把它改成**构建追踪号**，方便区分同一周的多次编译：

```
01.<两位年>.<ISO 周>.<当周第几次构建>

01.26.47.01   → 2026 年第 47 周第 1 次构建
01.26.47.05   → 同一周第 5 次
01.26.48.01   → 跨周后重置为 1
```

由 `tools/gen_version.py` 统一生成，写入两处：

| 文件 | 用途 |
|---|---|
| `version`（仓库根目录） | 发布标记，和上游结构保持兼容 |
| `include/version_sg.h` | `SG_VER_MAJOR / YEAR / WEEK / BUILD` 宏 |

```bash
python tools/gen_version.py            # 自增一次并写入
python tools/gen_version.py --show     # 只看当前值
python tools/gen_version.py --no-bump  # 沿用当前值（重编同一天用）
```

> **编号会烧进固件并上报给打印机**：`src/bus/bambu_bus_ams.cpp` 把 4 个宏填进版本帧，切片软件「设备 → 固件更新」里 AMS 的版本就显示成 `01.26.47.01` 这种格式。
>
> 上游 V11 是写死的 `0x00 0x00 0x00 0x0B`（即 `11.00.00.00`），我们换成构建追踪号后，每次编译都能在打印机上看到具体是哪一版。

---

### 序列号里也能看出变体

打印机「设备 → 固件更新」里显示的 AMS 序列号是 15 位：

```
B 0 C  2 A C 7 D A 5  A 1 1 3 0
│      │              │ │ │ │ └── 耗材灯：1 = 开，0 = 关
│      │              │ │ │ └──── 退料长度：0=0.20f 1=0.50f 2=0.70f 3=0.90f
│      │              │ │ └────── 档位：1=soft 2=standard 3=high_force
│      │              │ └──────── 自动进料：1 = 开，0 = 关
│      │              └────────── 槽位：A~D = A~D 槽，0 = 自动注册
│      └───────────────────────── UID：芯片派生 7 位（28 位，2.68 亿种）
└──────────────────────────────── 标识：B0C = BMCU 开源固件
```

所以 `B0C2AC7DA5A1130` = A 槽、自动进料**开**、档位 1（soft_load）、退料 0.90f、耗材灯**关**。

**看配置只需要最后 5 位**——`A1130` 就够了，不用整串。

- 前 3 位 `B0C` 是 BMCU 标识（`BMCU` 的 `M`/`U` 不是十六进制字符，用 `0` 代替 `O`）
- UID 7 位 = 28 位，2.68 亿种，多台同机也不会重号
- 官方 AMS 序列号同样是 15 位，长度与显示格式兼容

## 八、配套：BMCU-BusSentry-SG 总线哨兵

部分打印机固件对配件认证周期有一个约 **132 秒**的打印宽限期。**BMCU-BusSentry-SG 总线哨兵**（另一个项目）接在 BambuBus 上，在配件认证周期内对 BMCU 发起静默指令从而实现自动续期：

```
打印机 ──RS485──┬── BMCU（本仓库固件）
                └── BMCU-BusSentry-SG（旁听 + 在合适时机发 0x04A0）
                          ↓
                BMCU 静默 → 重启 → 重新注册 → 宽限期刷新
```

**没有总线哨兵时，本仓库固件仍可当普通 BMCU 使用**，只是不会自动续期。

**总线哨兵项目**（源码不公开，只提供硬件资料与固件）：
- 硬件设计（PCB / 原理图 / BOM）与固件 `.bin`：立创开源工程 https://oshwhub.com/sg-diy/project_tactlhci
- 固件：`.bin` 随硬件工程附件提供，直接烧录即可；**不提供源码**

### 诊断接口（0x04A1 / 0x04A2）

固件 ≥ `01.26.47.10` 起支持只读诊断。刷好后在**总线哨兵**网页的「数据诊断」页点「读取 A/B/C/D」或「全部读取」，即可看到该槽位的数据：

| 系统健康 | 四通道明细（每通道一行）|
|---|---|
| 运行时长、重启原因、上次注册、固件版本（含变体）、循环周期（均值 / 峰值）| 压力 %、缓冲电压、触发电压、触发状态（无 / 外部 / 内部 / 双）、角度、磁铁、编码器、装料、卡料 |

- **一问一答**：只在点按钮时查询（每槽约 0.5 ms 总线时间），不做周期广播
- 静默窗口 / 重启过程中不回包，页面会提示「BMCU 静默中（重启中）」
- 需要哨兵固件 ≥ `26.1124.002`（诊断 v3）；协议由哨兵与 BMCU 固件约定，规格不单独公开
- 未知请求不应答；**不发诊断请求的哨兵/打印机完全不受影响**
