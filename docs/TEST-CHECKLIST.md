## 六、预期中的「正常异常」（2026-11-19 实测确认）

| 现象 | 是否正常 | 原因 |
|---|---|---|
| 打印过程中出现 HMS 认证错误（`attr 0x05000500 / 0x05010500`，`code 0x00010014`）| ✅ 正常 | **打印任务开始后自动闸门不工作 → 宽限期不刷新 → BMCU 无官方认证必失败 → 但不影响打印** |
| 打印结束后 HMS 自动消失 | ✅ 正常 | 闸门静默 → BMCU 重启重新注册 → 旧认证记录被清除 |
| 空闲时 `ams_exist_bits` 在 3↔2↔1 之间抖 | ✅ 正常 | 闸门每 112 秒静默一轮，AMS 重启后重新注册 |

> 若「打印结束后 HMS 一直不消失」，先看闸门是否触发（哨兵 `/gatestatus` 的 `cuts` 有没有涨）。
> 实测时间线见哨兵仓库 `docs/gate.md` 第十一节。

## 七、诊断接口专项验证（2026-11-22 起）

> 前提：哨兵固件 ≥ `26.1122.018`，BMCU 固件 ≥ `01.26.47.10`。
> 入口：哨兵网页「数据诊断」→「读取 A/B/C/D」；**不需要打印机**（诊断由哨兵主动发问）。

```
□ 出表格：四通道表格 + 系统行（时长/重启原因/注册/静默/总线错误/循环）
□ 槽位对：读 A 返回 slot=A；读不存在的槽位约 1.9 s 后显示「无响应」
□ 重启原因：哨兵发一次静默、BMCU 重启后，应显示「软件复位」
□ 角度：手转送料齿轮 1/4 圈，角度变化约 90°（±5%）
□ 触发：拨动微动，触发列在 无/外部/内部/双 之间变化
□ 卡料：人为堵料 → 卡料列置位，且 AMS 报文压力变 0xF06F
□ 打印中读：不产生 HMS、打印状态与 remain 不变
□ 连点 10 次：哨兵 /info 的 frames 正常增长，/log 无 [slow] 告警
```
